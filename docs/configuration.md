## Configuration Files

Agent OS uses two configuration files:

| File | Location | Purpose |
|------|----------|---------|
| Base Config | `~/agent-os/config.yml` | System-wide defaults |
| Project Config | `<project>/agent-os/config.yml` | Project-specific settings |

Project configurations inherit from base configuration but can override settings.

---

## Base Configuration

Located at `~/agent-os/config.yml`:

```yaml
version: 2.1.1
base_install: true

# CONFIGURATION
# Configure defaults for the tools you use and how Agent OS should compile commands for your projects.

# ================================================
# Do you use Claude Code?
# Set to true to install commands in your project's .claude/commands/agent-os/ folder
#
# Override this default when running project-install.sh by using the flag --claude-code-commands=true/false
# ================================================
claude_code_commands: true

# ================================================
# Do you use other coding tools (Cursor, Windsurf, etc.)?
# Set to true to install commands in your project's agent-os/commands/ folder
#
# Override this default when running project-install.sh by using the flag --agent-os-commands true/false
# ================================================
agent_os_commands: false

# ================================================
# Do you want Claude Code to use subagents?
# Set to true to install agents in .claude/agents/agent-os/ and have commands delegate to them
# Requires claude_code_commands: true
#
# Override this default when running project-install.sh by using the flag --use-claude-code-subagents true/false
# ================================================
use_claude_code_subagents: true

# ================================================
# Should standards be provided to Claude Code as Skills?
# Set to true to use Claude Code's Skills feature for reading standards
# Set to false to inject standards as file references in command prompts
# Requires claude_code_commands: true (automatically treated as false if claude_code_commands is false)
#
# Override this default when running project-install.sh by using the flag --standards-as-claude-code-skills true/false
# ================================================
standards_as_claude_code_skills: false

# ================================================
# PROFILE
#
# Use this profile by default.
#
# Override this default when running project-install.sh by using the flag --profile [profile-name]
# ================================================
profile: default
```

## Project Configuration

Located at `<project>/agent-os/config.yml`:

```yaml
# Agent OS Project Configuration
# This file is automatically generated during project installation

version: 2.1.1
base_install: false

# Profile used for this project
profile: default

# Feature flags (as configured during installation)
claude_code_commands: true
use_claude_code_subagents: true
agent_os_commands: false
standards_as_claude_code_skills: false
```

## Configuration Options

### Core Options

#### `version`
- **Type**: String (semver)
- **Required**: Yes
- **Description**: Agent OS version
- **Example**: `2.1.1`
- **Note**: Auto-managed, do not edit manually

#### `base_install`
- **Type**: Boolean
- **Required**: Yes
- **Description**: Whether this is a base or project installation
- **Values**: `true` (base), `false` (project)
- **Note**: Auto-set, do not edit manually

#### `profile`
- **Type**: String
- **Required**: Yes
- **Default**: `default`
- **Description**: Profile to use for standards and workflows
- **Example**: `rails`, `nextjs`, `django`
- **Override**: `--profile <name>` flag

### Feature Flags

#### `claude_code_commands`
- **Type**: Boolean
- **Default**: `true`
- **Description**: Install Claude Code slash commands
- **Location**: `.claude/commands/agent-os/`
- **Override**: `--claude-code-commands true/false`
- **When to use**: Always for Claude Code users

#### `use_claude_code_subagents`
- **Type**: Boolean
- **Default**: `true`
- **Description**: Delegate work to specialized subagents
- **Requires**: `claude_code_commands: true`
- **Location**: `.claude/agents/agent-os/`
- **Override**: `--use-claude-code-subagents true/false`
- **Benefits**: Context efficiency, specialized expertise
- **Trade-offs**: Higher token usage, less transparency

#### `agent_os_commands`
- **Type**: Boolean
- **Default**: `false`
- **Description**: Install CLI-based commands
- **Location**: `agent-os/commands/`
- **Override**: `--agent-os-commands true/false`
- **When to use**: For Cursor, Windsurf, or manual workflows

#### `standards_as_claude_code_skills`
- **Type**: Boolean
- **Default**: `false`
- **Description**: Use Skills feature for standards discovery
- **Requires**: `claude_code_commands: true`
- **Override**: `--standards-as-claude-code-skills true/false`
- **Benefits**: Agent discovers standards when needed
- **Trade-offs**: Requires Skills feature setup
- **Note**: Run `/improve-skills` after enabling

## Profiles

Profiles define the standards, workflows, and templates for your project.

### Default Profile

Ships with Agent OS:
- **Location**: `~/agent-os/profiles/default/`
- **Contents**:
  - 8 specialized agents
  - 7 command workflows
  - 30+ workflow files
  - 15+ standards documents
- **Use case**: General-purpose projects

### Custom Profiles

Create custom profiles for specific tech stacks:

```bash
~/agent-os/scripts/create-profile.sh
```

**Profile Structure**:
```
~/agent-os/profiles/<profile-name>/
├── agents/              # AI agent definitions
├── commands/            # Command workflows
├── workflows/           # Detailed instructions
└── standards/           # Coding standards
    ├── global/
    ├── frontend/
    ├── backend/
    └── testing/
```

### Using Custom Profiles

```bash
# Install with custom profile
~/agent-os/scripts/project-install.sh --profile rails

# Or edit base config
nano ~/agent-os/config.yml
# Set: profile: rails
```

### Profile Examples

**Rails Profile**:
- Ruby/Rails specific standards
- RSpec testing conventions
- ActiveRecord patterns
- Hotwire/Turbo guidelines

**Next.js Profile**:
- TypeScript strict mode
- React best practices
- Next.js conventions
- Tailwind CSS patterns

**Django Profile**:
- Python PEP 8 standards
- Django ORM patterns
- pytest conventions
- Django REST framework

## Environment-Specific Settings

### Development vs Production

While Agent OS doesn't have built-in environment support, you can manage environments with:

**Option 1: Multiple Profiles**
```bash
# Create dev and prod profiles
~/agent-os/scripts/create-profile.sh
# Name: my-app-dev

~/agent-os/scripts/create-profile.sh
# Name: my-app-prod

# Use appropriate profile per environment
~/agent-os/scripts/project-install.sh --profile my-app-dev
```

**Option 2: Git Branches**
```bash
# Different config on different branches
git checkout development
# Edit agent-os/config.yml for dev settings

git checkout production
# Edit agent-os/config.yml for prod settings
```

**Option 3: Separate Directories**
```
project/
├── development/
│   └── agent-os/  # Dev config
└── production/
    └── agent-os/  # Prod config
```

### Example 1: Claude Code with Subagents (Default)

**Use case**: Maximum context efficiency, complex features

```yaml
# ~/agent-os/config.yml
claude_code_commands: true
use_claude_code_subagents: true
agent_os_commands: false
standards_as_claude_code_skills: false
profile: default
```

**Install**:
```bash
~/agent-os/scripts/project-install.sh
```

### Example 2: Claude Code without Subagents

**Use case**: Simpler workflow, single-agent execution, cost savings

```yaml
# ~/agent-os/config.yml
claude_code_commands: true
use_claude_code_subagents: false
agent_os_commands: false
standards_as_claude_code_skills: false
profile: default
```

**Install**:
```bash
~/agent-os/scripts/project-install.sh --use-claude-code-subagents false
```

### Example 3: Skills-Based Standards

**Use case**: Dynamic standards discovery, reduce prompt size

```yaml
# ~/agent-os/config.yml
claude_code_commands: true
use_claude_code_subagents: true
agent_os_commands: false
standards_as_claude_code_skills: true
profile: default
```

**Install**:
```bash
~/agent-os/scripts/project-install.sh --standards-as-claude-code-skills true
```

## Configuration Best Practices

### 1. Set Defaults in Base Config

Edit `~/agent-os/config.yml` with your most common settings:
```yaml
# If you always use Claude Code with subagents
claude_code_commands: true
use_claude_code_subagents: true

# If you have a custom profile
profile: my-company-profile
```

Then all project installations will use these defaults.

### 2. Override Per Project

For projects with different needs:
```bash
# Most projects use default
~/agent-os/scripts/project-install.sh

# Rails project uses custom profile
cd ~/rails-app
~/agent-os/scripts/project-install.sh --profile rails

# Experimental project uses skills
cd ~/experiment
~/agent-os/scripts/project-install.sh --standards-as-claude-code-skills true
```

### 3. Version Control Considerations

**Recommended `.gitignore`**:
```gitignore
# Keep standards and config
!agent-os/config.yml
!agent-os/standards/

# Ignore generated specs
agent-os/specs/*/implementation/
agent-os/specs/*/verification/

# Ignore Claude Code files (team preference)
.claude/
```

Some teams commit `.claude/` files, others don't. Choose based on:
- ✅ Commit if: Team wants shared agent definitions
- ❌ Don't commit if: Developers use different AI tools

### 4. Document Project Configuration

Add to your project's README:
```markdown
## Agent OS Configuration

This project uses Agent OS for AI-assisted development.

- **Profile**: rails
- **Claude Code**: Enabled with subagents
- **Standards**: Custom Rails standards in agent-os/standards/

### Setup
\`\`\`bash
~/agent-os/scripts/project-install.sh --profile rails
\`\`\`
```

## Configuration Validation

### Manual Validation

```bash
# Check base config syntax
cat ~/agent-os/config.yml | grep -v '^#' | grep -v '^$'

# Check project config
cat agent-os/config.yml

# Verify profile exists
ls ~/agent-os/profiles/<profile-name>/

# Check what would be installed
~/agent-os/scripts/project-install.sh --dry-run --verbose
```

### Common Issues

**Issue**: Commands not installed
```yaml
# Check this is true if using Claude Code
claude_code_commands: true
```

**Issue**: Agents not available
```yaml
# Check this is true
use_claude_code_subagents: true

# And this is true
claude_code_commands: true
```

**Issue**: Standards not working
```yaml
# If using Skills, ensure:
standards_as_claude_code_skills: true

# And run:
# /improve-skills in Claude Code
```
